# 本地试用后的开发优先级

日期：2026-09-29。依据当前源码和 HANDOFF_STUDIO 的验收证据。本文是后续建议，不新增已完成功能，也不代表已经调用真实服务或开始平台发布。

## 当前判断

项目已具备本地单人、US 英文普通单品的图文制作闭环。下一阶段应先让运营能持续使用并找回历史，再用真实商品验证质量。知识和审核的来源追溯已经有基础；本地排版还不能替代场景模型，mock 也不能证明真实提供方的质量、延迟或费用。

用户已决定服务商稍后选择，因此以下前三个切片不依赖外部模型密钥。开发智能体的 Astra/Luna 配置不参与运行时服务鉴权。

## 可以立即施工的三个切片

| 优先级 / 切片 | 用户收益与范围 | 验收标准 | 约束与风险 |
| --- | --- | --- | --- |
| P0：交付文件与数据恢复验收 | 完成实际桌面浏览器的 JSON/PNG/ZIP 下载落盘检查；提供清晰的本地启动、停止、整库备份与恢复流程 | 在隔离目录完成创建→审核→下载→停服→备份→新目录恢复；ZIP 包含正确版本及全部图片；恢复前后记录 ID 和图片哈希一致；Windows 路径含空格可用 | 先复现下载问题再决定是否改代码；仅有 API 通过不能关闭浏览器验收。恢复必须到新目录，不覆盖用户库，不在线复制不一致数据库 |
| P1：历史记录完整可访问 | 图片、图片运行记录、文案、批次、内容包按模块补齐分页或加载更多；显示总数并保持当前选择 | 构造超过单页上限的历史记录，可以查看早期成功、失败及中断记录；切换商品不串数据；翻页/刷新保留草稿和选中版本 | API 已有 offset/limit，先复用；不一次加载全部记录。按模块分别下施工单，避免多个 worker 改同一个页面 |
| P1：本地图片模板质量 | 为现有原图排版加入少量明确布局、文字换行和溢出提示、尺寸与安全边距预览；保存使用的布局版本 | 用长标题、中英文、透明图、横竖原图验证无裁字和失真；同一输入可追溯；布局或文字修改生成新候选并重新审核 | 不补造产品事实，不自动把卖点图当 Amazon 主图；如修改公共方案契约，由主代理先定默认值和历史兼容 |

以上切片的实现文件由各自施工单精确指定：下载/恢复涉及 `apps/web/src/*/api.ts`、下载动作及 `src/storage`/启动流程；历史分页涉及对应 Studio 组件与既有分页 API；图片模板涉及 `src/image/provider.ts`、图片方案契约和 ImageStudio。此处列依赖，不是授予跨模块任意修改权限。

## 真实商品试用与知识库下一步

使用用户选定的 5—10 个普通单品，准备资料、实拍图和来源说明。先跑本地流程，逐项记录：制作时间、人工修订次数、事实错误、图中文字可读性、原图一致性、下载结果和重启恢复情况。试用数据放独立运行目录，不进入 Git；“审核通过”必须来自实际人工核对。

知识库扩展按试用输入决定：

1. 若多人反复维护相同品牌要求，先设计可复用品牌规范及明确适用商品范围；生成保存引用快照，规范更新不静默重绑已审核版本。
2. 若资料主要是说明书 PDF，先做有页码来源的文本解析、解析失败提示和人工确认，再单独评估扫描件 OCR；导入不能自动确认事实。
3. 若文本数量已造成查找困难，再评估更好的检索与语义召回。任何召回仍限定商品/授权范围，最终生成引用具体已确认版本。

现有本地模板将知识保存为审核依据，并不自动把任意知识正文写入文案。若要自动使用其中的规格，应先定义结构化事实与冲突处理，再经人工确认或接入受约束的文字模型。

## 选定服务商后实施

先按 `PROVIDER_ADAPTERS.md` 接通一个文字服务、一个支持原图输入的图片服务。文字目前有默认可选实现，图片只有可注入接口和本地实现；各服务的真实能力需要分别联调。

验收除正常返回外，必须覆盖缺配置、认证失败、限流、超时、无效输出、断连、重复请求与重启。记录模型版本、实际用量和明确支持的取消/查询/幂等能力；费用没有可靠数据时保持未知。真实图片必须对照原图检查形状、颜色、配件与规格，不能只凭“图片返回成功”验收。

统一运行时状态与配置诊断可以先用 mock 建立；提供方接口选型、计费验证和真实质量结论须等服务商确定。密钥只由后端读取，不提交到仓库或发送到聊天中。

## 工程与较后阶段

- 建立自动回归入口：测试、类型检查、API/web 构建。当前没有 GitHub Actions 工作流；增加 CI 前先处理测试对 E 盘临时目录和固定端口的环境依赖，自动测试继续 mock 外部请求。
- 前端主包约 1.35 MB，按页面拆分加载可作为独立性能切片；验证首屏及切换耗时，避免只有体积变化没有体验证据。
- S8 每次启用一个明确目标站点/语言和品类，验证术语、单位、规则及独立版本。
- S9 等真实账户、应用授权和目标品类条件明确后，使用官方接口完成预检→审核确认→提交→回读。没有授权时可设计契约和 mock，不能声称发布联调完成。

## 协作方式与完成门槛

Astra 负责公共契约、架构、迁移和最终验收；Luna xhigh 每次独占一个有界施工单；独立 reviewer 检查 diff 和证据。建议先执行 P0 下载与恢复切片，再按试用反馈选择历史分页或模板质量。工程规范见 `docs/agents/construction-order.md`；后续工作继续记录为本地任务，不默认创建远端 issue。

进入更广泛试用的门槛是：文件可靠落盘、历史可访问、数据可恢复、失败可解释、图文事实经人工核对。进入真实 AI 使用和平台发布分别需要各自的外部联调证据。
