# S4：商品文案与知识依据

Status: ready-for-agent

目标：从保存的商品资料生成 US 英文文案，编辑为不可变版本，人工审核，导出并能重启回读。

## 约定

- 新契约在 `src/schemas.ts` 的 content studio 段。旧请求/响应不改变。
- 新接口位于 `/api/products/:productId/content`：列表、版本详情、生成、保存、生成记录、审核、导出。
- `POST /generate` 带客户端 `requestId`、`sourceRevisionId`、`baseContentVersionId`、选词、模式、知识版本列表。
- 同请求 ID 和同输入返回已有记录；同键不同输入返回冲突；失败后的新尝试使用新 ID，并保留旧记录。
- `PUT /content` 带基准文案版本和完整正文；冲突不覆盖他人新稿，相同正文不新增版本。
- 每份文案固定资料版本、知识引用、规则和生成来源。默认 US 英文，其他站点不伪装已支持。
- 模型失败返回明确运行状态，不静默称为模板成功。运行中的请求在正常停服时等待，异常恢复标记中断。
- 审核追加保存；文案编辑产生待审新版本。正式导出需批准且依据有效，草稿导出显式标记。
- 知识库未接通之前，非空知识引用必须明确拒绝；接通后只接收属于此商品的已确认版本。

## 必须验证

1. 原 v1 数据库升级保留商品、资料版本、原图记录及不可变约束；未知版本仍拒绝。
2. 两窗口编辑、生成期间 head 改变、跨商品 ID、同请求重放与不同输入冲突。
3. provider 配置缺失、异常、超长/无效输出不会伪装成功；运行记录可查询。
4. 商品资料或已引用知识更新后，历史内容可查但正式交付需复核。
5. UI 可输入/筛选关键词、明确主词、生成、编辑保存、核对历史、审核和下载。
6. 网络错误保留草稿；结果未知先查询任务/最新版本；跨商品迟到响应不覆盖页面。
7. 旧 CLI、graph、商品与原图、工作台导航保持原有行为。
