# 运行时服务适配边界

2026-09-29：用户选择先完成本地功能与适配接口，服务商稍后决定。

## 两类模型配置

`.codex/config.toml` 的 Astra/Luna 是开发智能体配置。产品运行时没有自动获得 Codex 订阅中的文字或图片权限，运行时密钥也不能来自浏览器表单或自动读取 Codex 登录凭据。

本地模式无需外部模型：文案模板按商品字段制作，选定知识固定保存为人工审核依据；卖点图由 sharp 直接把受控原图与独立文字层排版成 1600×1600 PNG，不改变产品形状，也不生成使用场景。

## 注入入口

`openCatalog(settings, faults?, { text?, image? })` 在后端装配依赖。测试通过参数注入 mock；实际服务商由后续独立适配器实现。HTTP 不允许提交任意模型端点、远程图片地址或本机文件路径。

- 文字：`ContentGenerator` 接收资料、关键词、模式、固定知识快照，返回满足 `ContentCopySchema` 的文案、来源和模型标识。默认实现继续使用既有服务端 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL` 可选配置，只有明确 `mode=model` 才调用；未配置、超时或无效输出保存失败记录，不静默回退成 AI 成功。
- 图片：`ImageProvider` 接收 `product`、已读取并验证的 `originalBytes`、`plan`、固定 `evidence` 和 `requestId`；只返回 JPEG/PNG 字节。必须声明取消、幂等、状态查询能力。所有输出仍由本地文件边界检查大小、像素、完整解码、哈希和不可覆盖存储。

图片 `mode=model` 默认没有服务商；场景请求保存 `IMAGE_PROVIDER_NOT_CONFIGURED` 失败状态。真实适配器必须自行实现有界超时、必要的 AbortSignal、鉴权、提供方错误转换和请求幂等能力，不能把任意返回 URL 交给通用 fetch。能力不支持时，界面不得宣称取消调用或停止计费。

任务在调用前记录 running 和固定输入，最多同时 2 项文案、2 项图片制作；批量文案顺序执行。服务退出等待已开始的 HTTP 操作；非正常退出的未完成任务下次启动标记 interrupted。用户明确创建新请求才重试，不能自动重放潜在收费请求。当前适配器没有可靠用量/价格数据，费用保持未知。

## 接入服务商时的验收

1. 选定具体模型/版本、端点、原图传送方式和使用条件，只在服务端配置密钥。
2. mock 验证鉴权失败、限流、超时、畸形结果、超大图片、重复请求和断连；错误不能包含密钥、原始响应或任意路径。
3. 用用户选定的少量真实商品对照原图与参数，分别记录模型输出质量和人工审核结果。当前合成数据测试不能替代这一步。
4. 记录服务商实际支持的取消/查询/幂等与用量信息，再开放相应按钮。

多站点本地化和 Amazon 官方发布是后续切片：需要明确目标站点/类目、规则证据和账户授权。现有 12 个 marketplace 配置不代表文案已翻译；本地批准包也不代表 Amazon 已接受或采用内容。
